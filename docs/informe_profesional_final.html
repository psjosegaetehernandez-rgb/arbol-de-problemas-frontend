1. Resumen Ejecutivo

La Red Nacional enfrentaba un dilema crítico: necesitaba centralizar datos de vulneraciones para generar incidencia política, pero el uso de herramientas tradicionales (Google Forms, Excel, nubes comerciales) exponía a personas migrantes a riesgos de filtración, persecución y acciones legales.

Como solución, se ha desarrollado una PWA (Progressive Web App) Local-First con arquitectura Zero-Knowledge y Cifrado de Extremo a Extremo (E2EE). Los datos se cifran en el dispositivo del voluntario antes de tocar la red. La plataforma permite la gestión de casos, exportación de documentos seguros, respaldos cifrados y generación de estadísticas protegidas mediante K-Anonimato.

2. Stack Tecnológico

  • Frontend: React 18 + TypeScript + Vite (por su velocidad y tipado estricto).
  • Estilos: CSS modular (diseño Responsive adaptado para Android).
  • Base de Datos Local: IndexedDB mediante Dexie.js (permite funcionamiento offline).
  • Criptografía: Web Crypto API nativa (Estándar W3C).
  • Generación de Documentos: pdf-lib (Generación de PDFs en el lado del cliente).
  • PWA: vite-plugin-pwa (Instalación en pantalla de inicio y Service Workers).

4. Características de Seguridad Implementadas

4.1. Cifrado E2EE (AES-256-GCM)

La app no usa contraseñas simples. Utiliza PBKDF2 (con 100.000 iteraciones) para derivar una llave criptográfica de 256 bits a partir del "Token de Caso" ingresado por el voluntario. Los datos (texto, imágenes y PDFs) se cifran y descifran exclusivamente en la memoria RAM del dispositivo.

4.2. Control de Acceso Basado en Capacidades (CapBAC)

No existen "usuarios globales". Al crear un caso, el sistema genera un Token único (ej. A1B2-C3D4). Este token es la única llave para abrir esa carpeta. El sistema no guarda el token en texto plano, garantizando que solo el administrador que lo creó pueda entregarlo.

4.3. Gestión Documental Cifrada

Los voluntarios pueden subir fotos o PDFs. El archivo se convierte a Base64, se cifra con la llave del caso y se guarda en IndexedDB. Al descargarlo, se descifra en memoria. La nube nunca ve la imagen original.

4.4. Borrado Seguro (Data Erasure)

Se implementó una "Zona de Peligro" que requiere confirmación explícita por texto para eliminar un caso de la base de datos local, evitando borrados accidentales de información sensible.

5. Privacidad Estadística: K-Anonimato (k=5)

Para evitar que un caso único en una ciudad pequeña identifique a una persona, el Dashboard (Panel General, Informes y Red Nacional) aplica la regla de K-Anonimato.

Regla de Negocio: Si una agrupación (por región o categoría) tiene entre 1 y 4 casos, la interfaz muestra el texto Agrupado (<5) en color mostaza. Cuando la cifra llega a 5, se revela el número real. Esto permite hacer incidencia política demostrando la existencia del problema sin señalar individuos.

6. Resiliencia y Respaldos (Zero-Knowledge)

El mayor riesgo del E2EE es la pérdida del dispositivo. Se implementó un módulo de exportación .json.enc en la pantalla de Configuración:

  • El sistema extrae todos los blobs cifrados de la base local.
  • El administrador define una "Contraseña de Respaldo".
  • El archivo se cifra nuevamente con esta contraseña y se descarga.
  • La restauración (Importar Respaldo) descifra el archivo y repuebla IndexedDB en un dispositivo nuevo.

7. Simulación de la Red Nacional (Servidor Ciego)

Para demostrar la escalabilidad del modelo, se implementó una vista de "Estadísticas" que simula un servidor ciego central. Los voluntarios presionan "Sincronizar a la Nube", enviando únicamente los metadatos públicos (Región, Categoría, Fecha) y el blob cifrado. La coordinación de la Red ve las tendencias comparativas en tiempo real, cumpliendo el sueño de la incidencia política macro sin vulnerar la privacidad.

8. Despliegue (PWA)

La aplicación está configurada como PWA (Progressive Web App). Los voluntarios pueden ingresar desde Chrome en su Android y seleccionar "Agregar a la pantalla principal". La app se abrirá a pantalla completa, ocultando la barra de navegación, y tendrá un diseño adaptado (Responsive) con menú de hamburguesa y botones táctiles grandes.

9. Próximos Pasos (Roadmap a Producción)

  1. Backend Real: Migrar el simulador de localStorage a una base de datos central (PostgreSQL) y almacenamiento de objetos (AWS S3) con políticas estrictas de acceso.
  2. Gestión de Identidad: Implementar Passkeys/WebAuthn para evitar el ingreso manual de tokens largos.
  3. Auditoría de Seguridad: Realizar un Pentesting externo sobre el flujo de derivación de llaves (PBKDF2) y las políticas de CORS.
  4. Cifrado de PDFs: Integrar qpdf-wasm para que los reportes exportados soliciten contraseña al abrirse.
