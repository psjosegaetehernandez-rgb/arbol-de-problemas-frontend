1. Resumen Ejecutivo

La Red Nacional de Migrantes y Promigrantes requería una herramienta para centralizar casos de vulneración de derechos sin exponer a las personas ante riesgos de filtración, persecución o cambios legislativos adversos. La solución implementada abandona los modelos tradicionales (como Google Forms/Drive) y adopta una arquitectura Local-First con Cifrado de Extremo a Extremo (E2EE). Los datos viven descifrados únicamente en la memoria del dispositivo del voluntario y viajan/almacenan como blobs incomprensibles.

2. El Principio Rector: Zero-Knowledge

La plataforma garantiza que ni el servidor, ni el proveedor de la nube, ni un atacante que intercepte el tráfico, puedan leer la información. Esto se logra mediante el uso de la Web Crypto API nativa del navegador.

"Si la nube es hackeada o requerida por una autoridad judicial, solo se encontrarán archivos con números aleatorios (ciphertext), no nombres ni relatos de personas."

4. Flujo Criptográfico (Token de Acceso)

Para no depender de usuarios y contraseñas globales, se implementó un modelo de Control de Acceso Basado en Capacidades (CapBAC). El acceso se otorga a nivel de carpeta (Caso), no a nivel de plataforma.

  1. Derivación de Llave: Cuando el administrador genera un Token (ej. "X7-9A"), la aplicación usa PBKDF2 (con 100.000 iteraciones) para transformar ese texto en una llave criptográfica única (DEK).
  2. Cifrado: Todos los datos de la carpeta se cifran con esa llave AES-256-GCM.
  3. Acceso: El voluntario ingresa el Token. La app deriva la llave, intenta descifrar el Blob y si el Token es incorrecto, el descifrado falla (error de autenticación GCM).

5. Privacidad Estadística: K-Anonimato

Un sistema de incidencia política necesita estadísticas, pero una estadística de "1 caso" en una ciudad pequeña rompe el anonimato de la persona. Se implementó la regla de K-Anonimato con k=5.

En el Dashboard (Panel General, Informes y Red Nacional), cualquier agrupación (por región o categoría) que sume entre 1 y 4 casos se reemplaza visualmente por el texto Agrupado (<5) en color mostaza. Cuando el número llega a 5, se revela el dato real. Esto permite hacer incidencia política sin señalar individuos.

6. Resiliencia y Gestión de Claves (Respaldos)

La mayor debilidad del cifrado E2EE es la pérdida de datos por robo o rotura del dispositivo. Se desarrolló un módulo de exportación .json.enc:

  • Extrae todos los blobs de IndexedDB.
  • Los empaqueta en un JSON.
  • El usuario define una "Frase de Recuperación".
  • El JSON se cifra con esa frase y se descarga.
  • La restauración ocurre 100% en el cliente de la nueva PC. El servidor nunca ve la frase de recuperación.
